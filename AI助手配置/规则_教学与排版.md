## 教学规范

| # | 规范 |
|:-:|:----|
| 1 | 例题必须带通用公式 + 逐步代入计算，不能跳步 |
| 2 | 有题型总览表的地方必须加直达链接，点题型能跳到例题 |
| 3 | 笔记链接用 Obsidian WikiLinks `[[链接]]` |

## 排版格式

| # | 规则 | 说明 |
|:-:|:----|:-----|
| 1 | **可折叠答案** | 用 `> [!答案]-` Obsidian 原生 callout，**禁止用 `<details>`**——会阻断 KaTeX 公式渲染 |
| 2 | **行内公式单位** | `$...\mathrm{kg}$` 优先用 `\mathrm`，`\text` 在部分行内公式场景渲染失败；含中文的场景才用 `\text`（如 `$g_{\text{月}}$`） |

## 题目与答案格式标准

适用于所有数学/物理/代码类笔记中的例题、习题、概念题。

### 题目格式

```markdown
### 题 N — 可选标题（或 ### 例题 N — 标题）

题目描述文字，纯文本，**不要**放在 > 引用块内。
多行问题直接写，每行独立。

> [!答案]- 点击展开
>
> **① 写公式（或分析）：**
> $$
> 通用公式
> $$
>
> **② 代入：**
> $$
> 代入具体数值，带单位换算
> $$
>
> **③ 结果：**
> $$
> 最终答案 + 单位
> $$
>
> **计算步骤总结：**
> - 第一步：做什么
> - 第二步：做什么
> - 第三步：做什么
```

### 格式铁律

| # | 规则 | 正确✅ | 错误❌ |
|:-:|:----|:------|:-------|
| 1 | **题目是纯文本，不是引用块** | `题目内容...` | `> 题目内容...` |
| 2 | **答案用可折叠 callout** | `> [!答案]- 点击展开` | `<details>` 或直接显示 |
| 3 | **三步法：公式→代入→结果** | 每步清晰分隔 | 一大坨公式甩脸上 |
| 4 | **必须有步骤总结** | `**计算步骤总结：**` + 列表 | 只给答案不给思路 |
| 5 | **单位换算写在代入步** | 代入前统一转国际单位 | 数字带不同单位直接算 |
| 6 | **判断命题题先贴原命题** | 答案折叠块上面先列原命题，再给判断+解析 | 直接写"❌ 错"不贴原话 |

## 代码注释模板（大白话风格）

适用于笔记里所有代码块（C / Python 等）。**每行一句人话**，讲"这行在干嘛"，不堆专业术语；关键循环 / 易错行补一个具体运行例子。

### 示例

```c
int n;                                 // 一个整数变量 n，存"要多大数组"
printf("请输入数组大小: ");             // 提示用户输入
scanf("%d", &n);                       // 输入一个 n（存进 n）

// 给 n 个 int 分配内存，让 arr 指向它
int *arr = (int*)malloc(n * sizeof(int));

if(arr == NULL) {                      // 分配失败：malloc 返回 NULL
    printf("分配失败！\n");
    return 1;                          // 提前结束，绝不能用 NULL 指针
}

for(int i = 0; i < n; i++) {
    arr[i] = i + 1;                    // 第 i 格填 i+1
    // 例：n=5 → i=0 填 arr[0]=1 … i=4 填 arr[4]=5，最后 1 2 3 4 5
}

free(arr);                             // 把内存还给系统
arr = NULL;                            // 防悬空指针：free 后立刻置 NULL
```

### 四条标准

| # | 规则 | 正确 ✅ | 错误 ❌ |
|:-:|:----|:------|:------|
| 1 | **每行一句大白话**，讲"这行干嘛"，不堆语法术语 | `scanf("%d",&n); // 输入一个 n` | `scanf("%d",&n); // %d 是整数格式符…` |
| 2 | 注释靠右对齐，代码本体一眼看全 | 代码在左，注释右对齐 | 长注释把代码挤乱 |
| 3 | 关键循环 / 易错点补一个具体运行例子 | `// 例：n=5 → 1 2 3 4 5` | 只抽象描述不举例 |
| 4 | 错误示范用 ❌ 标明，正确做法单独列 | `// ❌ …` + `// 正确做法：` | 好坏代码混一起不标 |
